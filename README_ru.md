# APTCP-SOCKS Tunnel

**APTCP-SOCKS Tunnel** — это асинхронный SOCKS5 прокси-сервер и клиент поверх сеансового протокола **APTCP** (`aioptcp`), обеспечивающий высокую отказоустойчивость и непрерывность сетевого соединения при кратковременных обрывах связи, переключении между интерфейсами (Wi-Fi/LTE) или смене IP-адресов.

Проект поддерживает полный функционал **SOCKS5 (RFC 1928)**, включая **TCP CONNECT** и **UDP ASSOCIATE** (для SOCKS5-клиентов, таких как Proxifier, Postern и др.), а также авторизацию по стандарту **RFC 1929** через `.jsonl` файлы.

---

## Архитектура и особенности

* **Отказоустойчивость сетевого соединения:** При кратковременном сбое сети логический канал SOCKS5 не разрывается, а буферизирует данные. `aioptcp` автоматически восстанавливает физический TCP-канал в фоновом режиме без потери передаваемых данных.
* **Поддержка UDP-трафика:** Полная реализация команды `UDP ASSOCIATE`. Проксирует UDP-датаграммы в обе стороны через единый устойчивый туннель.
* **Двухуровневая авторизация:**
  1. Авторизация приложения $\rightarrow$ SOCKS5 Client (RFC 1929 Username/Password).
  2. Авторизация SOCKS5 Client $\rightarrow$ APTCP Server (Туннельная аутентификация).
* **Конфигурация пользователей через JSONL:** Удобное хранение пар `{"username": "...", "password": "..."}`.
* **Поддержка TLS-шифрования:** Опциональное шифрование трафика между клиентом и сервером с проверкой сертификатов.

## Развертывание сервера на Linux

Для серверной части поддерживаются два сценария развертывания: автоматический через Docker Compose и ручной.

### Вариант А: Развертывание через Docker Compose (Рекомендуемый)

Это наиболее простой способ развертывания, не требующий установки интерпретатора Python и зависимостей на хост-систему.

1. Скопируйте на ваш Linux-сервер следующие файлы и папки проекта:
   * `common/`
   * `server/`
   * `Dockerfile`
   * `docker-compose.yml`
   * `requirements.txt`
2. Создайте файлы конфигурации из примеров:
   ```bash
   cp server/config.json.example server/config.json
   cp server/users.jsonl.example server/users.jsonl
   ```
3. (Опционально) Отредактируйте параметры авторизации в `server/users.jsonl` и порты в `server/config.json`. По умолчанию используется порт `1080`.
4. Запустите сервис в фоновом режиме:
   ```bash
   docker compose up -d
   ```
5. Проверить статус работы и логи можно командой:
   ```bash
   docker compose logs -f
   ```

---

### Вариант Б: Ручной запуск на сервере

1. Убедитесь, что в системе установлен Python 3.11+.
2. Установите необходимые зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Скопируйте шаблоны конфигурации:
   ```bash
   cp server/config.json.example server/config.json
   cp server/users.jsonl.example server/users.jsonl
   ```
4. Настройте параметры авторизации в `server/users.jsonl`.
5. Запустите сервер:
   ```bash
   python -m server.main server/config.json
   ```

## Пояснение по авторизации (Два уровня паролей)

В данном проекте используется двухэтапная авторизация. Чтобы не запутаться, обратите внимание на различие между локальной и туннельной авторизацией:

### 1. Локальная авторизация (Ваше приложение &rarr; Локальный клиент)
* **На что влияет:** Разрешает или запрещает вашему приложению (например, Proxifier) подключаться к локально запущенному прокси на порту `1080`.
* **Где настраивается:** На стороне клиента в `client/config.json` с помощью флага `"auth_enabled"` и файла `client/users.jsonl`.
* **Как это работает:**
  * Если `"auth_enabled": true`, в настройках прокси в Proxifier **необходимо** поставить галочку «Аутентификация» и ввести логин и пароль из файла `client/users.jsonl` (например, `proxifier` / `proxifier_password`).
  * Если `"auth_enabled": false`, Proxifier пустит к локальному прокси **без ввода пароля** (в настройках Proxifier выберите тип аутентификации *«None»* / *«Без авторизации»*). При этом сам туннель до сервера все равно будет защищен!

### 2. Авторизация в туннеле (Локальный клиент &rarr; Удаленный APTCP-сервер)
* **На что влияет:** Разрешает локальному клиенту установить защищенный туннель с удаленным сервером.
* **Где настраивается:** В `client/config.json` (поля `"aptcp_username"`, `"aptcp_password"`) и на сервере в `server/users.jsonl`.
* **Как это работает:**
  * Локальный клиент **в любом случае** берет логин и пароль из своего `client/config.json` и отправляет их для авторизации на удаленный сервер.
  * **В Proxifier эти данные вводить не нужно!** Программа Proxifier ничего не знает об авторизации туннеля, клиент выполняет её под капотом автоматически.

## Настройка и запуск клиента

Клиент работает на локальной машине пользователя и принимает соединения от локального SOCKS5-клиента (например, Proxifier).

1. Скопируйте пример конфигурации:
   ```bash
   cp client/config.json.example client/config.json
   ```
2. Отредактируйте `client/config.json`, указав:
   * `aptcp_server_host`: IP-адрес или домен вашего удаленного Linux-сервера.
   * `aptcp_server_port`: Порт, на котором запущен APTCP-сервер (по умолчанию `1080`).
   * `aptcp_username` / `aptcp_password`: Данные учетной записи, прописанные на сервере в `users.jsonl`.
3. Задайте параметры авторизации для локальных программ, скопировав и заполнив файл пользователей:
   ```bash
   cp client/users.jsonl.example client/users.jsonl
   ```
   *(Учетные данные из этого файла необходимо будет ввести в настройках Proxifier/Postern).*
4. Запустите клиентское приложение:
   ```bash
   python -m client.main client/config.json
   ```

## Настройка TLS (Шифрование туннеля)

Для защиты передаваемого трафика от анализа сетевыми провайдерами и DPI-системами рекомендуется включить шифрование TLS между SOCKS5-клиентом и APTCP-сервером.

### 1. Генерация самоподписанных сертификатов
На вашем Linux-сервере сгенерируйте приватный ключ и сертификат:
```bash
openssl req -x509 -newkey rsa:2048 -keyout server/key.pem -out server/cert.pem -days 365 -nodes -subj "/CN=ваш_домен_или_ip"
```
*Убедитесь, что файлы `key.pem` и `cert.pem` сохранены внутри директории `server/`.*

### 2. Настройка сервера
Включите поддержку TLS в файле `server/config.json`:
```json
{
  "aptcp_host": "0.0.0.0",
  "aptcp_port": 1080,
  "auth_enabled": true,
  "users_file": "server/users.jsonl",
  "timeout": 30,
  "tls_enabled": true,
  "tls_cert": "server/cert.pem",
  "tls_key": "server/key.pem"
}
```
*При использовании Docker Compose раскомментируйте строки монтирования сертификатов в `docker-compose.yml` перед запуском контейнера.*

### 3. Настройка клиента
1. Скопируйте файл публичного сертификата сервера (`cert.pem`) с сервера на клиентскую машину под именем `client/server_cert.pem`.
2. Активируйте TLS в конфигурационном файле `client/config.json`:
   ```json
   {
     ...
     "aptcp_tls_enabled": true,
     "aptcp_tls_ca_cert": "client/server_cert.pem"
   }
   ```
   *Если вы используете самоподписанный сертификат и не укажете параметр `aptcp_tls_ca_cert`, клиент переключится в режим без проверки подлинности сертификата (что небезопасно и не рекомендуется для промышленной эксплуатации).*
